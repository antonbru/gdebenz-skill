# GdeBenz API (gdebenz.ru)

Карта АЗС России по отметкам водителей: наличие бензина, очереди, лимиты, цены. **Данные краудсорсинговые** — статусы обновляют сами водители и могут быть устаревшими. Не выдавать за гарантию; при наличии показывать свежесть отметки.

База: `https://gdebenz.ru/api/`

## Приоритеты (по умолчанию)

- **95-й бензин — приоритет.** Показывать станции, где `fuels_now` содержит `95`.
- Если **совсем нет** станций с 95-м — на самый край показать с 92-м (пометка «только 92»).
- **Комментарии водителей важны**: для топ-3..5 станций дёргать `/api/comments/{osm_id}/recent` и показывать суть (что отметили, когда, на месте ли).

> Эти значения — пример. Настройте под себя: см. раздел «Настройка под себя» ниже и `config.example.yaml`.

## Эндпоинты

- `GET /api/stations?lat1=&lon1=&lat2=&lon2=` — АЗС в bbox. **Работает без авторизации и без токена.** 200 → JSON array.
- `GET /api/cities?q=<query>` — поиск города (lat/lon/zoom). Работает.
- `GET /api/comments?lat1=..&lon1=..&lat2=..&lon2=..` — сводка отметок по АЗС в bbox: `{osm_id, lat, lon, status, fmask, fresh_band, conflict}` (fmask — битовая маска топлива, fresh_band — свежесть, больше = свежее).
- `GET /api/comments/{osm_id}/recent?limit=12` — последние комментарии конкретной станции: `{status, detail, created_at, edited, on_site}`. `detail` — что отметил водитель («95», «очередь 20 мин», «лимит 10л»), `on_site` — на месте ли, `created_at` — UTC.
- `GET /api/price` — цены.
- `GET /api/rt` — отдаёт `{"rt":"...","ttl":1800}` — токен для заголовка `X-RT` (фронт ставит его на некоторые запросы; для чтения `/api/stations` не нужен).
- `GET /api/geosuggest?q=` — геокодер адреса. **Отключён сервером (404 по состоянию на 2026-08)** — не закладываться на него; для адрес→координаты использовать свой геокодер (Яндекс.Геокодер / OSM Nominatim) или `/api/cities` для уровня города.
- Прочее (`/api/station-suggestions`, `/api/me/state`, `/api/chats/*`, `/api/views`, `/api/rum`) — не нужно для чтения АЗС.

## Формат станции

```json
{
  "osm_id": "244205852",
  "name": "Роснефть",
  "brand": "Роснефть",
  "lat": 55.7012509,
  "lon": 37.605104,
  "addr": "Загородное шоссе, 2Б",
  "status": "yes",
  "fuels_now": "92,95,ДТ",
  "conflict": "queue",
  "prices_now": {"92": {"p": 65.6, "n": 3, "t": "2026-08-15 19:08:07"}, "95": {...}, "ДТ": {...}}
}
```

- `status`: `"yes"` / `"no"` / `null` — есть ли топливо. `null` ≠ «нет», просто нет отметки.
- `fuels_now`: строка с доступным топливом («92,95,ДТ»), может быть пустой.
- `conflict`: `"queue"` и т.п. — показать как ⚠️.
- `prices_now[<топливо>]`: `p` — цена, `n` — число отметок, `t` — время последней отметки (свежесть данных).

## Рабочий флоу «где бензин рядом»

1. **Координаты:** даны — используй; дан адрес — геокодируй (Яндекс.Геокодер / OSM Nominatim; site geosuggest отключён).
2. **Bbox:** `lat1=lat-Δ&lon1=lon-Δ&lat2=lat+Δ&lon2=lon+Δ`; Δ ≈ 0.05 ≈ 11×11 км.
3. **Запрос:** `GET https://gdebenz.ru/api/stations?...` с `User-Agent` браузера и `Referer: https://gdebenz.ru/`. curl: `-L --compressed`.
4. **Обработка (приоритеты по умолчанию):**
   - Фильтр 1: `status == "yes"` и `"95" in fuels_now` → отсортировать по расстоянию, топ-5..8.
   - Если таких 0 → фильтр 2: `status == "yes"` и `"92" in fuels_now` (пометка «только 92»).
   - Показать: расстояние, станция, адрес, статус, топливо, цены 92/95, свежесть (`t`), конфликт (очередь).
5. **Комментарии:** для топ-3..5 станций `GET /api/comments/{osm_id}/recent?limit=12` → взять 1–3 свежих `detail` (с `created_at` и `on_site`), вписать в ответ.
6. Станций в bbox бывает 100+, поэтому всегда топ-N по расстоянию (5–8), а не всё подряд.

## Настройка под себя

Все параметры — через переменные окружения (работают и в скрипте, и как подсказка агенту):

| Переменная | Значение по умолчанию | Описание |
|---|---|---|
| `GB_API_FUEL` | `95` | Приоритетное топливо (92, 95, ДТ, …) |
| `GB_API_FALLBACK` | `92` | Запасное топливо, если основного нет нигде. Пусто — без fallback |
| `GB_API_RADIUS` | `5` | Радиус поиска, км |
| `GB_API_TOP_N` | `8` | Сколько станций показывать |
| `GB_API_COMMENTS` | `1` | Показывать комментарии водителей (`0` — выключить) |
| `GB_API_COMMENT_N` | `5` | Для скольких станций тянуть комментарии |

Пример: хотите только дизель в радиусе 10 км без комментариев — задайте `GB_API_FUEL=ДТ`, `GB_API_RADIUS=10`, `GB_API_COMMENTS=0` (в `config.example.yaml` есть готовый шаблон). В Hermes/OpenClaw переменные можно прописать в окружении агента; либо просто поправьте секцию «Приоритеты» в этом файле — агент будет следовать ей.

## Telegram

- **Если сообщение пришло из Telegram** (платформа доставки = telegram) и координат нет — в конце ответа предложить: «Пришли геолокацию (📎 → Геопозиция / Location) — найду точнее».
- Если пользователь уже прислал геолокацию — использовать её lat/lon напрямую.
- Ответы — по-русски, по делу, таблицей (в Telegram markdown рендерится).

## Питфоллы

- **Ответ сжатый (brotli)** — `curl` без `--compressed` вернёт бинарную кашу; с `--compressed` нормально. Python `urllib` декодирует прозрачно.
- `/api/stations` отдаёт **301** без следования редиректу — `curl -L` или urllib (фолловит сам).
- Цены и статусы краудсорс: у одной станции может быть `status=yes`, но пустой `fuels_now`; у другой цены есть, а статуса нет. Показывать оба поля и свежесть.
- Топливо в `fuels_now` через запятую — искать подстроку, не точное равенство.
- Внутри bbox попадаются станции за его пределами (граница) — не критично, но при строгом радиусе отсекать по расстоянию.

## Скрипт

`scripts/nearest_stations.py <lat> <lon> [radius_km] [fuel]` — готовый флоу: bbox → запрос → сортировка → фильтр → таблица + комментарии. CLI-аргументы перекрывают переменные окружения. Проверен на живом API (Москва, 114 станций в bbox).
